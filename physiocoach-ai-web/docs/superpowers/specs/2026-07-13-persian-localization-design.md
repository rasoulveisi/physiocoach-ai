# Persian Interface Localization Design

## Objective

Add Persian as a user-selectable interface language while retaining English as the default and fallback language. Persian copy should be clear, modern, and friendly. This phase covers only app-owned interface text; content returned by the API or generated by AI remains unchanged.

## Scope

The localization must cover all built-in user-facing copy in public, authenticated, onboarding, dashboard, workout plan, workout session, posture assessment, progress, measurements, settings, shared UI, and admin screens. This includes:

- Headings, body copy, navigation labels, buttons, links, and menu items
- Form labels, placeholders, options, help text, and validation messages
- Loading, empty, error, confirmation, and success states
- Toasts, dialogs, tooltips, and other programmatic interface messages
- App-owned accessibility labels and alternative text
- Page metadata and the no-JavaScript message where they are controlled by the application

The following are explicitly out of scope for this phase:

- Exercise names and descriptions returned by the API
- AI-generated workout instructions and safety notes
- Server-provided error text
- Locale-specific conversion of dates, numbers, measurements, or units
- Additional languages beyond English and Persian

## Architecture

Use `@ngx-translate/core` with `@ngx-translate/http-loader` and Angular standalone providers. Runtime JSON files will be stored at:

- `public/i18n/en.json`
- `public/i18n/fa.json`

English is the default and fallback language. The application loads the saved language preference during startup. If no preference exists, it selects English regardless of the browser locale. The language selector is placed in Settings and applies changes immediately without navigation or reload.

Translation keys are grouped by stable feature namespaces such as `COMMON`, `NAV`, `LANDING`, `AUTH`, `ONBOARDING`, `DASHBOARD`, `WORKOUT_PLAN`, `WORKOUT_SESSION`, `POSTURE_ASSESSMENT`, `PROGRESS`, `MEASUREMENTS`, `SETTINGS`, `ADMIN`, and `ACCESSIBILITY`. Keys describe semantic purpose rather than using English copy as the identifier.

Templates use the ngx-translate pipe or directive. TypeScript-defined interface messages use the translation service. App-owned copy must not remain duplicated as raw English strings after migration, except for deliberate technical values that are not displayed to users.

## Language State and Data Flow

A focused localization service wraps ngx-translate and owns the supported-language list, current language, persistence, and document direction. Its public operations are limited to initializing language state and selecting a supported language.

At application startup:

1. Read the stored language code.
2. Accept it only if it is a supported value (`en` or `fa`).
3. Select `en` when the value is missing or invalid.
4. Load the corresponding JSON resource with English configured as fallback.
5. Apply the matching document language and direction before normal interaction begins.

When the user changes the language in Settings:

1. Switch ngx-translate to the selected locale.
2. Set the root document to `lang="fa"` and `dir="rtl"` for Persian, or `lang="en"` and `dir="ltr"` for English.
3. Persist the supported language code locally.
4. Let reactive translations update the current view immediately.

Invalid persisted values are ignored. A Persian-resource load failure must leave the app usable with English fallback copy and must not block startup.

## RTL and Typography

Persian changes the entire document to RTL. Direction-sensitive layout should use logical CSS properties and direction-aware flex/grid behavior instead of page-specific mirroring hacks. Existing English LTR behavior must remain unchanged.

The implementation must audit:

- Shell and mobile navigation order and alignment
- Directional icons such as arrows, chevrons, and next/previous controls
- Forms, validation messages, inputs, and selectors
- Number-range pickers and increment/decrement controls
- Cards, status rows, dialogs, and action groups
- Charts, legends, and metric tiles
- Long Persian labels at narrow mobile widths

Use a font stack that renders Persian clearly while preserving the current English typography. Brand names and API-returned LTR text should remain legible when embedded in an RTL page. Mixed-direction content may receive local direction isolation where required.

## Translation Quality

Persian copy should favor natural, concise product language over literal word-for-word translation. Medical and exercise terminology should be accurate but approachable. Terminology must remain consistent across screens, especially for assessment, posture, workout plan, session, repetitions, sets, measurements, progress, and safety concepts.

English JSON is the canonical key set. Persian JSON must maintain structural parity with it. Interpolated values and markup must use the same parameter names in both languages.

## Testing and Verification

Automated coverage will include:

- English is selected when there is no stored preference.
- A stored Persian preference is restored during initialization.
- Unsupported stored values safely resolve to English.
- Selecting a language persists it and updates ngx-translate.
- Selecting Persian sets `lang="fa"` and `dir="rtl"`; selecting English restores `lang="en"` and `dir="ltr"`.
- A missing Persian translation resolves to the English fallback rather than exposing a raw key.
- English and Persian JSON resources have identical key structures.
- Representative template and TypeScript messages render translated values.

Manual verification will cover all routes in both languages at desktop and mobile widths, with particular attention to overflow, direction-sensitive icons, forms, navigation, charts, number pickers, dialogs, and mixed-direction API content.

The final implementation must pass linting, the complete automated test suite, and a production build.

## Acceptance Criteria

- English remains the default on a first visit.
- Settings provides English and Persian language choices.
- The selected language persists across reloads and app restarts.
- All app-owned interface and accessibility copy is available in both JSON files.
- Persian switches the whole interface to RTL and renders cleanly on supported screen sizes.
- English remains LTR with no visual regression.
- Missing or failed Persian translations fall back safely to English.
- API- and AI-provided content is displayed unchanged.
- Translation parity and localization-state behavior are covered by automated tests.
- Lint, tests, and production build pass.
